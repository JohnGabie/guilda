# Lab: click a reference and open the right place

Date: 2026-11-09. Branch: `lab/links`. Spec: `docs/superpowers/specs/2026-11-09-guilda-0.2-design.md`, D33 and D27.
Prepared by a dispatched agent (D19). The clicks are a user step.

## Hypothesis

A reference such as `D14` or a file path, shown by guilda, opens the right file at the right line when the user
clicks it (Ctrl+click or click), in the program that the user set, in each place where the user reads guilda output.

## PASS criteria (written before the run)

| ID | Check | PASS |
|---|---|---|
| L1 | Formats | The agent prepares the same target (the first line of block D14 in the spec) in each candidate format: plain `path:line`, an absolute `path:line`, a `vscode://file/<path>:<line>` link, a terminal hyperlink (OSC 8) to that link, a Markdown link, and an ID in the panel mod if the mod can open a file. |
| L2 | Commands | Without the user: `code --goto <path>:<line>` and `zed <path>:<line>` (if installed) open the file at the line. The agent records the exit code and what it can check. |
| L3 | Places | The user clicks each format in: the Claude Code chat in the kitty terminal, the kitty terminal itself (a script output), and, if the user uses them, Claude Code inside VS Code and the desktop app. |
| L4 | Result | For each place: the formats that open the right file at the right line in 3 of 3 tries. PASS if each place has at least one such format. |
| L5 | Config | The result maps to one setting in `.guilda/config.json` (for example `links.open`), and `guilda:init` can ask it. |

## Method

1. Find the target with `grep -n '^### D14' docs/superpowers/specs/2026-11-09-guilda-0.2-design.md`.
2. `labs/links/show-links.mjs` reads the spec and finds the line of `### D14`. It prints the target in each
   format (A to I) with a label. It writes real OSC 8 escapes. It takes the paths from its own location, so the output
   is correct in each checkout. `labs/links/links.md` has the relative Markdown links for an editor or a reader.
3. Read the type file of the mod API (`plugin-authoring/types/claude-code.d.ts`, Claude Code 2.1.321) and the
   panel mod on `lab/agent-panel` (`labs/agent-panel/guilda-panel`). Research only, no change to the mod.
4. Find the programs: `which code zed kitty xdg-open`, `xdg-mime query default` for the type of the spec file and
   for `x-scheme-handler/vscode`, `kitty --version`, `code --help`, `zed --help`. Read the hyperlink options in
   `~/.config/kitty/kitty.conf` and the kitty defaults in its `options/definition.py`. Read only.
5. The agent did not open an editor on the screen of the user. The user does the clicks (L3, L4) with the
   checklist below.

## Evidence

### L1 — Formats

Target: `docs/superpowers/specs/2026-11-09-guilda-0.2-design.md`, line 633 (`### D14 — Agent queue in code`).

| Key | Format | Text (`<abs>` is the absolute path of the checkout) |
|---|---|---|
| A | relative `path:line` | `docs/superpowers/specs/2026-11-09-guilda-0.2-design.md:633` |
| B | absolute `path:line` | `<abs>/docs/superpowers/specs/2026-11-09-guilda-0.2-design.md:633` |
| C | `vscode://` URL | `vscode://file<abs>/docs/superpowers/specs/2026-11-09-guilda-0.2-design.md:633` |
| D | `file://` URL | `file://<abs>/docs/superpowers/specs/2026-11-09-guilda-0.2-design.md` (no line) |
| E | OSC 8 to `file://` | text `D14 (file)`, target D |
| F | OSC 8 to `vscode://` | text `D14 (vscode)`, target C, ST terminator |
| G | OSC 8 to `vscode://` | the same as F, BEL terminator |
| H | Markdown, relative | `[D14](docs/superpowers/specs/2026-11-09-guilda-0.2-design.md#L633)` |
| I | Markdown, `vscode://` | `[D14](vscode://file<abs>/...:633)` |

A `file://` URL has no standard place for a line. A click on D or E can open the file, but not at line 633.

The panel mod (D20) can do it. Facts from the type file, not tested live:

- `Link` (`LinkProps.href`, "any scheme"): an OSC 8 span on the terminal, an anchor on the desktop. "What a click
  opens is the surface's." On a remote surface, only an `https:` link stays a link.
- `Markdown` draws links only for `https:`, `http:` and `file:`. A `vscode://` link in it is plain text. With
  `onLinkPress`, the mod gets the press and can act.
- `Button` with `onPress` plus `$.process.run(argv)` runs a command on the host with no shell, for example
  `["code", "--goto", "<abs>/<spec>:633"]` or `["zed", "<abs>/<spec>:633"]`. This opens the exact line and does not
  depend on the terminal.
- The panel mod on `lab/agent-panel` has no `Link` and no `$.process` call now. Its rows have `Button` with
  `onPress`, so a row for an ID can use the same pattern.

### L2 — Commands

The agent recorded the commands. It did not run them, so that no editor opened on the screen of the user.

| Program | Found | Version | Opens at a line |
|---|---|---|---|
| VS Code | `/usr/bin/code` | 1.144.0 | `code --goto <file:line[:character]>` (from `--help`) |
| Zed | `~/.local/bin/zed` | — | `zed <path>:<line>:<column>` (from `--help`: "path:line:column syntax") |
| kitty | `/usr/bin/kitty` | 0.47.1 | not an editor |
| xdg-open | `/usr/bin/xdg-open` | — | no line |

- `xdg-mime query filetype` of the spec gives `text/plain` (not `text/markdown`). The default app for
  `text/plain` is Zed (`dev.zed.Zed.desktop`). The default app for `text/markdown` is Scribe
  (`io.github.gnacho.Scribe.desktop`). So a `file://` click through `xdg-open` opens the spec in Zed, at the top.
- The handler of `x-scheme-handler/vscode` is `com.microsoft.VSCode.UrlHandler.desktop`. So a `vscode://` link
  that reaches `xdg-open` goes to VS Code.
- `kitty.conf` sets none of `allow_hyperlinks`, `open_url_with`, `url_style`, `detect_urls` and `mouse_map`.
  There is no `open-actions.conf` and no `launch-actions.conf`. So kitty uses its defaults:
  `allow_hyperlinks yes`, `open_url_with default` (the system opener), `url_style curly`, `detect_urls yes`.
- kitty default mouse maps: a plain left click opens a link when the program does not grab the mouse. Shift+click
  opens it when the program grabs the mouse. Ctrl+Shift+click opens it in both cases. Ctrl+click alone has no
  default map in kitty. This is important for the D33 words "Ctrl+click".
- kitty `detect_urls` finds text with a URL scheme (C, D). It does not find a plain `path:line` (A, B).

### User checklist (L3, L4)

Run the script in kitty: `node labs/links/show-links.mjs` from the repo root. For each place and each key, try 3
times. Write: what opened (program), which file, which line, and the click that worked (plain click, Ctrl+click,
Shift+click, Ctrl+Shift+click).

1. kitty, the raw output of the script (no Claude Code): click A to I. Expected by the defaults: C, D, E, F, G
   are links; A and B are not.
2. The Claude Code chat in kitty: paste the lines A, B, C and H into the chat. Click the same lines in the answer
   of Claude. Also try the lines while the mouse is grabbed (Shift+click).
3. VS Code with Claude Code (only if you use it): paste A, B, C and H in the panel. Then open
   `labs/links/links.md` in VS Code. Click its links in the editor and in the Markdown preview.
4. The desktop app (only if you use it): paste A, B, C and H in a chat and click each.

Report for each place: the keys that open the spec at line 633 in 3 of 3 tries.
