# Lab: click a reference and open the right place

Date: 2026-11-09. Branch: `lab/links`. Spec: `docs/superpowers/specs/2026-11-09-guilda-0.2-design.md`, D33 and D27.
Prepared by a dispatched agent (D19). The clicks are a user step.

## Hypothesis

A reference such as `D14` or a file path, shown by guilda, opens the right file at the right line when the user
clicks it (Ctrl+click or click), in the program that the user set, in each place where the user reads guilda output.

A `file://` URL has no standard place for a line. A click on D or E can open the file, but not at line 633.

The panel mod (D20) can do it. Facts from the type file, not tested live:

- `Link` (`LinkProps.href`, "any scheme"): an OSC 8 span on the terminal, an anchor on the desktop. "What a click
  opens is the surface's." On a remote surface, only an `https:` link stays a link.
- `Markdown` draws links only for `https:`, `http:` and `file:`. A `vscode://` link in it is plain text. With
  `onLinkPress`, the mod gets the press and can act.
- `Button` with `onPress` plus `$.process.run(argv)` runs a command on the host with no shell, for example
  `["code", "--goto", "<abs>/<spec>:633"]` or `["zed", "<abs>/<spec>:633"]`. This opens the exact line and does not
  depend on the terminal.
- The panel mod on `lab/agent-panel` has no `Link` and no `$.process` call now. Its rows have `Button` with
  `onPress`, so a row for an ID can use the same pattern.

### L2 — Commands

The agent recorded the commands. It did not run them, so that no editor opened on the screen of the user.

| Program | Found | Version | Opens at a line |
|---|---|---|---|
| VS Code | `/usr/bin/code` | 1.144.0 | `code --goto <file:line[:character]>` (from `--help`) |
| Zed | `~/.local/bin/zed` | — | `zed <path>:<line>:<column>` (from `--help`: "path:line:column syntax") |
| kitty | `/usr/bin/kitty` | 0.47.1 | not an editor |
| xdg-open | `/usr/bin/xdg-open` | — | no line |

- `xdg-mime query filetype` of the spec gives `text/plain` (not `text/markdown`). The default app for
  `text/plain` is Zed (`dev.zed.Zed.desktop`). The default app for `text/markdown` is Scribe
  (`io.github.gnacho.Scribe.desktop`). So a `file://` click through `xdg-open` opens the spec in Zed, at the top.
- The handler of `x-scheme-handler/vscode` is `com.microsoft.VSCode.UrlHandler.desktop`. So a `vscode://` link
  that reaches `xdg-open` goes to VS Code.
- `kitty.conf` sets none of `allow_hyperlinks`, `open_url_with`, `url_style`, `detect_urls` and `mouse_map`.
  There is no `open-actions.conf` and no `launch-actions.conf`. So kitty uses its defaults:
  `allow_hyperlinks yes`, `open_url_with default` (the system opener), `url_style curly`, `detect_urls yes`.
- kitty default mouse maps: a plain left click opens a link when the program does not grab the mouse. Shift+click
  opens it when the program grabs the mouse. Ctrl+Shift+click opens it in both cases. Ctrl+click alone has no
  default map in kitty. This is important for the D33 words "Ctrl+click".
- kitty `detect_urls` finds text with a URL scheme (C, D). It does not find a plain `path:line` (A, B).

### kitty: how a click on a link opens (source of kitty 0.47.1)

- `window.py`, `open_url`: for an OSC 8 link, kitty does nothing if `allow_hyperlinks` is `no`. For a `file:` URL
  with a host, a host that is not this machine goes to the `remote_file` kitten. `allow_hyperlinks ask` shows a
  question first. Then `boss.open_url`.
- `boss.py`, `open_url`: kitty first looks for a match in `open-actions.conf`. If no rule matches, it runs
  `open_url_with` (`default` is `xdg-open` on Linux, `utils.py`, `command_for_open`). The URL, with its fragment,
  goes to `xdg-open` as it is. `xdg-open` has no place for a line.
- `open_actions.py`: kitty reads `open-actions.conf` from its config directory. The match keys are `protocol`,
  `mime`, `ext`, `file`, `path`, `url` and `fragment_matches`. The action gets `$URL`, `$FILE_PATH`, `$FILE`,
  `$FRAGMENT` (the part after `#`, unquoted), `$URL_PATH`, `$NETLOC`, `$EDITOR` and `$SHELL`. The first rule that
  matches wins. Without a user rule, only the `kitty+doc` rule exists. So with no `open-actions.conf`, a click on
  a `file://` link always goes to `xdg-open`.
- Found in the source: kitty makes the value of each match key lower case, except `url`. So
  `fragment_matches ^L?[0-9]+$` becomes `^l?[0-9]+$`, and `#L633` does not match. The test files use
  `(?i)^l?[0-9]+$`. The kitty docs do not say this.
- The config directory: `KITTY_CONFIG_DIRECTORY`, if set, is always used (`kitty --help` text). `--config` changes
  only `kitty.conf`, not the directory of `open-actions.conf`. So `try-kitty.sh` uses `KITTY_CONFIG_DIRECTORY`
  with a temporary directory. Its `kitty.conf` has `include ~/.config/kitty/kitty.conf`. A load test showed the font
  and the shell of the user in the result, so the include works. It sets `tab_bar_style powerline`, because the
  custom tab bar of the user loads `tab_bar.py` from the config directory.
- A custom scheme works without an xdg handler: kitty looks in `open-actions.conf` before `xdg-open` for each
  scheme. Test: a rule `protocol guilda` matched `guilda://open/x.md#L633` (`$FRAGMENT` = `L633`) and `guilda:D14`.
  `url_prefixes` is only for URLs in plain text (`detect_urls`). An OSC 8 link with any scheme is clickable.
- The docs on `allow_hyperlinks`: "Process hyperlink escape sequences (OSC 8). If disabled OSC 8 escape sequences
  are ignored. ... The special value of `ask` means that kitty will ask before opening the link."
  On `open_url_with`: "The program to open clicked URLs."

### L6 — References in the replies of the assistant (mod API, Claude Code 2.1.321)

Facts from the type file and `reference.md`, not tested live:

- `ui.render` can draw `AssistantMessage`. Its props: `text` (the Markdown of the block, as the surface draws it),
  `isFirstOfReply`, `isSummary` (read only), `onScreen` (read only). A hook "rewrites them with
  `next({ ...e, props })`". An invalid rewrite draws the original.
- So a mod can change the text of a reply before it is drawn. It replaces each reference with a Markdown link. The
  model writes plain text. The work is code in the mod, so it costs no model tokens.
- `Markdown` (the same renderer as a reply) draws links only for `https:`, `http:` and `file:`. "A link not
  `https:`, `http:` or `file:` draws as text." So a `vscode://` or `guilda://` link in a reply stays text. A
  `file://` link with a fragment is possible.
- A hook can also answer with its own tree: a `Markdown` with `key`, `onLinkPress` and `pressableLinks`. A press
  raises `ui.press` with `link.href`, and the mod can run `$.process.run(argv)` (no shell), for example
  `open-at-line.mjs`. But a press is "a plain single click where the surface reports clicks (the fullscreen
  terminal)". Elsewhere, and on Ctrl or Alt click, the surface opens the link itself.
- `Link` (`href`: "any scheme", at most 2048 characters) is an OSC 8 span on the terminal. On a remote surface only
  `https:` stays a link. It is an element for a mod tree, not for the text of a reply.
- So the plan for L6: rewrite `text` to `file://` links with the line in the fragment. In kitty, a click goes to the
  open actions of L7 (less at the line, `git show` for a commit). In the fullscreen terminal, `onLinkPress` can run
  the opener directly. One link form works on both paths.
- Not verified: does Claude Code draw a Markdown `file://` link in a reply as an OSC 8 link in kitty? The first user
  result shows raw OSC 8 text. That is a different case: escapes inside the text.

`labs/links/linkify.mjs` is a sketch of the rewrite (no dependencies, 0.09 s for the sample below on this repo):

- An ID (`D33`, `R19`): the first `##`-`####` heading with that ID in a tracked Markdown file. The block index of
  D27 can take this place.
- A commit hash (7 to 40 hex digits): only if `git rev-parse --verify` finds a commit. The link is
  `file://<repo>#commit=<hash>`.
- A path or a bare file name, with an optional `:line`: only if exactly one tracked file matches. More than one
  match: the text stays plain (the ambiguity rule).
- Text in a fenced code block stays plain. Inline code that is a reference becomes a link with the code inside.

Sample output (`<root>` is the checkout):

```
[D33](file://<root>/docs/superpowers/specs/2026-11-09-guilda-0.2-design.md#L561) needs [D14](...#L633) and
[R19](file://<root>/core/rules.md#L96). See [`show-links.mjs:42`](file://<root>/labs/links/show-links.mjs#L42),
[open-at-line.mjs](...) and [kitty.conf](file://<root>/labs/links/kitty/kitty.conf).
```

A test can show that a reply cannot carry `file://` links. Then the closest path with no tokens is a band or a pane
of the mod. It lists the references of the last reply as `Markdown` links with `onLinkPress`. Or it lists them as
`Button`s with `$.process.run`.
