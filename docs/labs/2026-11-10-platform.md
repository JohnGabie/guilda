### P4 — `claude plugin eval`

- Case form (from `claude plugin eval --help` and the docs page "Test plugins with evals"): a case is a folder
  that holds `prompt.md` (frontmatter: `max_turns`, `timeout_seconds`, `allowed_tools`, `runs`, `tags`, `env`,
  ...; body: the prompt) and/or `case.yaml` (`schema_version: "1.1"`, `name`, `context.scaffold_script`,
  `context.history_file`, `context.add_dirs`, `graders`), plus `graders/*.md` (frontmatter `type`: `regex`,

  `evals/init/evals.json` of the branch is the skill-creator format; `claude plugin eval` does not read it.
- `--eval-dir`: "Directory name (below the plugin)"; the docs accept `quality/evals`. Command run:
  `claude plugin eval . --eval-dir evals/l6-sample --case 'empty-new-project' --runs 1 -j 3 --threshold 0.8

  the case: `--eval-dir evals/<suite>` works for one suite. No `results/` folder was written in the plugin
  copy.
- `--case` matches the case name: the `name` field, default the case folder name (`empty-new-project`). A filter

- Fixture: `case.yaml` `context: { scaffold_script: fixture.sh }` and `--scaffold`. The script ran in the empty
  workspace (`git init`, `package.json`); stderr shows `scaffold: .../fixture.sh` for each arm.

## Lessons

- A dependency that is not installed or out of range stops the plugin from loading, in a live session and in an
  eval. The eval config is new and empty, so each dependency of `guilda-skills` (superpowers, skill-creator) is
  unmet there: the evals of the extension cannot load it as the manifest is planned.
- `claude plugin eval` sessions are isolated: no user plugins, no user settings, `AskUserQuestion` absent, Bash
  only by grant and in the sandbox. The "with/without" difference is against no plugins at all.
- A `--plugin-dir` plugin that fails to load still hides the installed plugin of the same name.
- Pass an absolute `--plugin-dir` path when the session runs in another cwd (3 runs were lost to this).
